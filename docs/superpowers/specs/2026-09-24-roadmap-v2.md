# Feuille de route v2 — d'un audit pour experts à un copilote de mesure pour tous

## Vision

Un propriétaire de site, même novice, ajoute son site et sait : quoi installer
pour mesurer son trafic et ses conversions, ce qui ne va pas (CWV, SEO, tracking),
dans quel ordre le corriger, et se fait aider par un agent qui peut aller jusqu'à
proposer des changements dans son dépôt sous forme de pull requests. Un tableau
de bord suit tous ses sites dans le temps sur des KPIs pertinents.

## Décisions actées

- **Lancement : bêta fermée d'abord** (≤ 100 testeurs approuvés, pas de
  vérification OAuth Google au départ). La vérification Google est lancée **en
  parallèle** de la construction pour ouvrir au public ensuite.
- **Lecture seule côté Google** tant que la vérification n'est pas obtenue :
  toute « configuration » passe par des fichiers à importer, des snippets, des
  guides et, plus tard, des PR sur le dépôt de l'utilisateur.
- **Google Ads sans API** au départ (le developer token demande une approbation
  Google de plusieurs semaines) : détection, guide et conteneur GTM pré-rempli.
- **L'IA explique, le code décide** : aucun statut ni sévérité ne dépend d'un LLM
  (essai Jev/TypeSafe du 2026-09-24 : pas meilleur que nos règles sur le backlog
  réel).
- Interface en français ; internationalisation hors périmètre.

## Contraintes structurantes

1. **Vérification Google** : sans elle, l'app reste limitée aux testeurs
   approuvés. Les scopes sensibles ou restreints (écriture GA4/GTM/Ads) rallongent
   le processus (évaluation de sécurité possible).
2. **Pas de tâche de fond aujourd'hui** : Cloud Run ne calcule que pendant une
   requête et Redis n'est pas utilisé. Le suivi planifié (lot B) passe par Cloud
   Scheduler → endpoint protégé + table de jobs.
3. **Accès au dépôt = accès au code d'autrui** : modèle de confiance strict
   (GitHub App, permissions minimales, jamais de push sur la branche par défaut,
   PR uniquement, relecture humaine) à concevoir dans le lot E.

## Lots

| Lot | Contenu | Dépend de | Nouveau scope/droit Google |
|---|---|---|---|
| **A. Plan de mesure guidé** | Check-list vivante par site, type de site détecté puis confirmé, deux niveaux de preuve, conteneur GTM sur mesure, guides et snippets | rien | aucun |
| **B. Suivi planifié + historique** | Fréquence choisie par site (journalier, 3×/jour, tous les 3 jours…), exécution automatique, historique des statuts et métriques, rapports périodiques | A (statuts à historiser) | aucun |
| **C. Dashboard multi-projets** | KPIs dans le temps sur tous les sites, tendances, comparaison | B (séries temporelles) | aucun |
| **D. SEO Search Console** | Analyse et évolution dans le temps, points bloquants classés par criticité, au-delà des 10 URLs et du score actuels | B | aucun |
| **E. Agent PR (GitHub puis GitLab)** | Branche + PR d'amélioration analytics/CWV à partir du plan et des exports GTM, galerie des PR avec diffs rouge/vert et points clés | A ; C/D pour cibler les améliorations | aucun côté Google (GitHub App) |
| **F. Configuration assistée GA4/GTM/Ads** | Écriture directe et API Google Ads | vérification Google + developer token | écriture GA4/GTM, Ads |

### Ordre recommandé

A → B → (C et D) → E → F.

- **A d'abord** : plus gros gain pour un novice, aucune dépendance.
- **B** est la fondation technique de C, D et de la récurrence qui fait revenir
  les testeurs.
- **E n'exige pas les scopes d'écriture Google** : l'agent modifie le dépôt de
  l'utilisateur, ce qui couvre l'essentiel du « configure pour moi » sans le
  risque de vérification.
- **F en dernier** : le plus risqué, conditionné à la vérification Google.

Chaque lot suit le même cycle : brainstorming → spec → plan d'exécution →
exécution en tâches avec revue par tâche et revue finale de branche → merge.
Le lot A est spécifié dans `2026-09-24-measurement-plan-design.md`.

## À trancher plus tard (pas maintenant)

- Facturation et quotas par plan (avant l'ouverture au public).
- Fournisseur d'e-mail réel pour les rapports périodiques (lot B ; aujourd'hui
  seul `ConsoleEmailSender` existe).
- Politique de confidentialité, conditions d'utilisation et dossier de
  vérification Google (à démarrer en parallèle du lot A).
- Hébergement des tâches de fond si Cloud Scheduler devient insuffisant.
